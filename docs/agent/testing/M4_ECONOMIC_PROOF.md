# M4 economic and collateral proof

Status: **economic and collateral proof merged in PR #38 with the M4 contract stack in PR #37; locally verified against the recorded source/build artifacts**.
The proof and stateful invariants are the accounting baseline for integration. Recheck them if
contract source, payout rules, or ABI numeric units change.

## Canonical mathematical trade rounding

Let the real LMSR cost, measured in ACON base units, be

```text
C(qYes, qNo) = b * ln(exp(qYes / b) + exp(qNo / b)),  b = 50e18.
```

For a successful trade, `MarketPricing` uses the directed intervals documented in
[`PRICING_ROUNDING.md`](PRICING_ROUNDING.md) to certify both base-unit roundings before returning:

- a buy charges `ceil(C(after) - C(before))`;
- a sell pays `floor(C(before) - C(after))`.

An exact-integer difference has the same buy and reverse-sell amount. Otherwise the buy is one
base unit greater than the reverse sell. This residue stays in market collateral; there is no
platform fee or arbitrary error buffer. A positive sale whose floor is zero reverts
`TradeTooSmall`. If an interval cannot certify both roundings, `PricingPrecisionExceeded` reverts
the quote and execution before token or position state changes.

For the reported regression, selling `10e18` YES from `(50e18, 50e18)` and buying it back from
`(40e18, 50e18)` produces:

| Direction | ACON base units |
|---|---:|
| Mathematical sell floor | `4,750,415,558,917,673,486` |
| Reverse-buy ceiling | `4,750,415,558,917,673,487` |
| Residue retained in collateral | `1` |

The expected values come from the independent 160/220-digit Decimal references generated by
`script/pricing_reference.py`, not from the Solidity interval implementation.

## Preterminal collateral inequality

Let `q_i` be the market quantities after accepted trade `i`, and define the signed real-potential
change

```text
delta_i = C(q_i) - C(q_(i-1)).
```

For a buy, the contract's collateral change is `ceil(delta_i)`. For a sell, `delta_i < 0` and
the collateral change is `-floor(-delta_i)`. In both cases the integer collateral change is at
least the real potential change:

```text
actualChange_i = delta_i + residue_i,  where 0 <= residue_i < 1 base unit.
```

The residues are zero for exact-integer differences and positive otherwise. With creator subsidy
`S = ceil(C(0,0)) = 34,657,359,027,997,265,471` base units, every reachable OPEN-market state
therefore satisfies

```text
collateral
  = S + sum(actualChange_i)
  = S + C(qYes,qNo) - C(0,0) + sum(residue_i)
  >= S + C(qYes,qNo) - C(0,0).
```

This is an inequality over the rounded trade ledger, not the superseded equality between
independently rounded 18-decimal potentials. Because `S >= C(0,0)` and stable log-sum-exp gives

```text
C(qYes,qNo) >= max(qYes,qNo),
```

the market remains able to pay either winning outcome:

```text
collateral >= max(qYes,qNo).
```

It also covers the conservative VOID reserve for integer base-unit quantities:

```text
ceil((qYes + qNo) / 2) <= max(qYes,qNo) <= collateral.
```

Rejected quotes, slippage failures, token-transfer failures, and uncertified pricing intervals
make no reachable accounting state, so they do not alter the induction.

## Settlement, claims, bonds and surplus

- Final YES or NO liability is the outstanding quantity of the winning side. Each winning base
  unit pays one ACON base unit.
- VOID reserves `ceil((qYes + qNo) / 2)`. Each wallet receives
  `floor((yesShares + noShares) / 2)` in one combined claim. Removing a wallet's shares and that
  floored payout cannot make the remaining ceiling reserve exceed remaining collateral; odd-unit
  dust remains in the market.
- A claim marks the wallet claimed, clears both positions, decrements both outstanding quantities,
  and decreases collateral before transfer. Duplicate claims revert.
- Challenge bonds are held in `totalChallengeBonds`, outside every market's collateral. A changed
  outcome refunds the bond. An upheld proposal moves it into that market's collateral. Both paths
  preserve `token balance = total collateral + total challenge bonds` for intended flows.
- Creator surplus is available only in a terminal state and only above the recomputed remaining
  liability. Withdrawing exactly that difference leaves collateral greater than or equal to the
  remaining liability.

These properties apply independently per market. Global totals reconcile the token ledger; they
do not authorize one market to spend another market's collateral.

## Executable proof

[`contracts/test/MarketEconomics.t.sol`](../../../contracts/test/MarketEconomics.t.sol) adds:

1. A deterministic regression locking the mathematical sell floor, reverse-buy ceiling, and
   one-base-unit residue for the reported vector.
2. A stateful trading handler over two markets and two wallets. It repeatedly buys and sells both
   outcomes while checking quote-to-collateral changes, position/quantity conservation, creator
   subsidy preservation, winning and VOID coverage, token conservation, and market isolation.
3. A stateful settlement handler over YES, NO, VOID, and challenged markets. It varies claim
   order, creator-surplus withdrawals, duplicate-claim attempts, and challenged-market settlement
   while checking payout units, remaining liabilities, separate bond escrow, global token
   reconciliation, and cross-market isolation.

The repository invariant profile runs 256 campaigns at depth 500. The two new invariant suites
perform 256,000 state-machine calls in addition to the retained 128,000-call historical M3
buy-only invariant.

Run the focused proof and the complete contract validation from `contracts/`:

```bash
forge test --match-path test/MarketEconomics.t.sol -vv
forge test
forge fmt --check
python3 script/pricing_reference.py --check
python3 script/export_handoff.py --check
```

Fresh Sepolia deployment, real VRF behavior, Safe ownership, and whole-application integration
remain separate release gates; this proof does not claim they are complete.
